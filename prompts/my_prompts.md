8. 请按以下方案修复删除流程，不要再采用“先从任务数组移除、3 秒后直接操作 localStorage”的做法。
    1. 在 taskStore.js 中保留待删除任务于原来的 tasks 数组。用普通 Map 保存每个任务的定时器，用 Vue 响应式 Set 保存需要从界面隐藏的任务 ID。
    2. markPendingDelete(id)：确认任务存在后，将 ID 加入隐藏集合并启动 3 秒定时器；此时不写 localStorage。返回是否成功。
    3. Column.vue 展示、搜索结果和列计数都过滤隐藏集合；store 的原始任务数组及 `_save(status)` 仍包含待删除任务。
    4. cancelDelete(id)：清除定时器和隐藏标记即可，不写 localStorage。即使期间创建了其他任务，也应能恢复。
    5. 定时器到期时调用统一的 commitDelete(id)：从数组移除任务，然后调用现有 `_save(status)`。若写入失败，立即把任务插回原位置并清除隐藏标记，让用户看到任务仍在，同时显示错误提示。无论成功失败，都清理定时器记录。不要在定时器中直接调用 `localStorage.setItem`。
    6. 撤销按钮的有效期与 3 秒删除期限一致；提交后不再显示可点击的撤销按钮。App.vue 仅在 markPendingDelete 成功时显示“已删除”提示。

    请验证以下场景后再声称修复完成：

    - 确认删除后，卡片和列计数立即更新；3 秒内撤销可恢复。
    - 待删除期间在同列创建任务，随后撤销，两个任务都保留；刷新后仍在。
    - 待删除期间刷新页面，原任务仍在，因为删除尚未提交。
    - 3 秒到期后任务从页面和 localStorage 消失，刷新后不再出现。
    - 模拟最终写入容量不足：没有未处理异常，任务重新显示，刷新后仍在。
    - 同列两个任务同时处于待删除状态时，分别撤销或到期，结果正确。
    - 排序写入失败时，数组位置和每个任务的 `order` 都保持原值。

10. 请只改进当前目录中任务管理应用的前端视觉，不修改任务增删改查、拖拽、搜索、主题持久化或 localStorage 逻辑。项目使用 Vue 3、Vite 和 Tailwind CSS。开始前检查 Git 状态，保留已有改动。

11. 请修改当前 Task Manager 的任务卡片拖拽效果。

    当前问题：拖动卡片时，浏览器的拖拽预览会跟随鼠标，但原列表中的卡片仍完整显示，看起来像复制出了第二张卡片。目标是实现“拿起卡片”的效果：拖拽开始后，卡片跟随鼠标移动，原位置不再显示同一张卡片；同列的其他卡片应自然补位。整个拖拽过程中不要同时显示两张完整卡片。

    请先检查 `src/components/TaskCard.vue`、`Column.vue`、`KanbanBoard.vue` 及相关状态管理。目前使用原生 HTML 拖拽；可以保留现有方案，也可以在确有必要时改用更合适的拖拽实现。不要简单地在 `dragstart` 中立即卸载源卡片，因为这可能导致浏览器取消拖拽。选择能稳定实现上述视觉效果的方式，并保持当前卡片样式。

    必须满足以下行为：

    1. 拖拽开始：鼠标旁只出现一张清晰的移动卡片；源列表中不再显示原卡片，其他卡片补位。不要出现闪烁、双卡片或突然取消拖拽。
    2. 拖到另一列并松开：任务只移动一次，目标列显示卡片，原列不再显示；列计数和本地存储结果正确。
    3. 在同一列松开：仍可调整顺序，刷新页面后顺序保持正确。
    4. 在列外松开、按 Esc 或拖拽被取消：卡片恢复到原来的列和位置，任务数据不变。
    5. 拖动过程中不要提前修改任务的状态或持久化数据；只在有效放下后提交变更。拖拽结束时清理所有临时样式和状态。
    6. 保持搜索过滤、卡片点击编辑、手机端现有操作方式、明暗主题以及目标列高亮正常工作。拖动结束不应误触发卡片编辑弹窗。

    完成后运行构建，并在浏览器中实际测试：跨列移动、同列排序、列外取消、Esc 取消，以及有搜索条件时的拖拽。请报告具体修改文件、测试结果和未解决的问题；不要改动无关界面或业务逻辑。
